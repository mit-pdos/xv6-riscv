# Отчёт о реализации `malloc` и `free` в xv6

## Изменения в проекте

Аллокатор K&R из `user/umalloc.c` заменён на Segregated Free List (SFL). Старый аллокатор хранил свободные блоки в одном кольцевом списке и искал в нём место для вставки при освобождении. В новой реализации свободные блоки распределены по классам размеров, а положение соседей известно из заголовков блоков. Это сокращает область поиска при выделении и позволяет объединять соседей без обхода списка свободных блоков.

| Файл | Изменение |
| --- | --- |
| [`user/malloc.c`](user/malloc.c) | Аллокатор SFL, расширение и сжатие кучи, трассировка. |
| [`user/umalloc.c`](user/umalloc.c) | Файл с реализацией K&R удалён. |
| [`user/user.h`](user/user.h) | Сохранены сигнатуры `malloc(uint)` и `free(void *)`, добавлена `malloc_debug(int)`. |
| [`user/malloctest.c`](user/malloctest.c) | Проверки на односвязном списке и отдельные сценарии для управления кучей. |
| [`Makefile`](Makefile) | `malloc.o` подключён к пользовательской библиотеке `ULIB`, программа `malloctest` включена в образ `fs.img`. |

`malloc` и `free` выполняются в пользовательском пространстве. Для чтения текущей верхней границы сегмента данных используется `sbrk(0)`. При росте и сжатии аллокатор вызывает обычный `sbrk`, который передаёт ядру `SBRK_EAGER`. Аргумент любого вызова, изменяющего границу, кратен `PGSIZE` (4096 байт). При успехе `sbrk` возвращает прежнюю границу, при ошибке — `SBRK_ERROR`. Код ядра работает через существующий интерфейс. [Обёртка `sbrk`](user/ulib.c#L153), [обработчик системного вызова](kernel/sysproc.c#L40), [размер страницы](kernel/riscv.h#L389).

## Архитектура аллокатора

### Формат блока

На RV64 заголовок `struct block` занимает 32 байта и выровнен на 16 байт. Пользовательская область начинается сразу за заголовком, поэтому возвращаемый указатель также выровнен на 16 байт.

| Поле | Назначение |
| --- | --- |
| `prev`, `next` | Соседи в двусвязном списке блоков, упорядоченном по адресу. |
| `size` | Полный размер блока от начала заголовка до его конца, включая пользовательскую область и возможный остаток выравнивания внутри блока. |
| `requested` | Размер запроса пользователя до выравнивания. У свободного блока поле равно нулю. |
| `available` | Признак свободного блока. Отдельное поле позволяет отличить занятой блок после `malloc(0)` от свободного. |
| `padding` | Число байтов выравнивания перед заголовком. Эти байты принадлежат аллокатору и учитываются отдельно от `size`. |

В свободном блоке первые 16 байт пользовательской области используются для `struct free_links` с двумя указателями на соседей по корзине. При повторном выделении эта область снова доступна целиком. Минимальные 48 байт блока складываются из 32 байт заголовка и 16 байт под ссылки, которые понадобятся после `free`. [Определения структур](user/malloc.c#L7).

```text
Занятый блок   [выравнивание перед блоком] [заголовок] [пользовательская область]
Свободный блок [выравнивание перед блоком] [заголовок] [free_links] [остаток]
                                         |<----------- size ---------------->|
```

### Два набора связей

- **Список по адресам.** `heap_first` и `heap_last` указывают на крайние блоки. Список содержит занятые и свободные блоки. При `free` достаточно проверить двух соседей. Если между соседями есть память, полученная прямым вызовом `sbrk` из приложения, они остаются раздельными.
- **Корзины свободных блоков.** `bins` содержит 22 головы двусвязных списков. Класс определяется по полному `size` блока. Верхняя граница каждого следующего класса вдвое больше предыдущей. Первая корзина содержит блоки до 64 байт включительно, вторая — свыше 64 и до 128, третья — свыше 128 и до 256. Последняя корзина содержит блоки свыше 64 МиБ. Внутри каждой корзины действует порядок вставки в голову.

После завершения `malloc` или `free` каждый свободный блок находится ровно в одной корзине, соответствующей его текущему размеру. Занятые блоки представлены только в списке по адресам. Два физически смежных свободных блока образуют один блок. Если размер свободного блока меняется, его связи в корзине обновляются с учётом нового класса.

### Рост и сжатие кучи

При исчерпании подходящих блоков аллокатор сначала проверяет свободный хвост. Если хвост заканчивается на текущей границе сегмента, его можно расширить, запросив страницы для недостающей части. В остальных случаях страницы образуют новый блок. Тот же путь обслуживает многостраничные запросы. При наличии достаточно большого свободного блока крупный запрос также может использовать корзины.

Если приложение ранее вызвало `sbrk` и оставило невыровненную границу, очередной заголовок размещается по ближайшему большему адресу, кратному 16. Разница сохраняется в `padding`. Величина запроса к ядру остаётся кратной странице. Сумма `padding + size` описывает принадлежащий аллокатору диапазон, включая начальные байты выравнивания. Благодаря этому при полном освобождении диапазона можно восстановить исходную границу, даже если она невыровнена.

При освобождении верхнего блока отрицательный `sbrk` возможен, когда его конец совпадает с текущей границей сегмента. Из свободного хвоста возвращается целое число страниц. Если после возврата остался бы ненулевой фрагмент, слишком маленький для заголовка и связей корзины, аллокатор удерживает ещё одну страницу. Внутренние свободные блоки остаются доступными для повторного использования. Прямое уменьшение границы приложением допустимо в пределах памяти, выделенной его собственными вызовами `sbrk`.

### Стоимость операций

Поиск начинается с класса нужного размера. В худшем случае просматриваются подходящие по классу корзины и проверяются размеры их блоков. Если `B` — число корзин, а `K` — число проверенных блоков, поиск занимает `O(B + K)`. Здесь `B` фиксировано и равно 22. Получение адресных соседей и их объединение требует постоянного числа операций с указателями. Вставка и удаление из корзины также меняют постоянное число ссылок, с вычислением класса при вставке и при удалении головы. Трассировка отдельно обходит список блоков и корзины, поэтому в обычных пользовательских программах по умолчанию выключена.

## Функции `user/malloc.c`

### Выравнивание и адреса блоков

- **`align_up(size)`** округляет переданное число или адрес вверх до кратного 16. Прибавляет 15 и сбрасывает четыре младших бита. Используется для вычисления размера блока по запросу и размещения заголовка при невыровненной границе. [Код](user/malloc.c#L38)
- **`block_end(block)`** возвращает адрес сразу за блоком. Вычисление идёт в байтах через `char *`. Результат используется при проверке смежности и совпадения конца блока с границей сегмента. [Код](user/malloc.c#L44)
- **`free_links(block)`** возвращает адрес пары ссылок корзины сразу после заголовка. Эти ссылки используются только пока пользовательская область свободна. [Код](user/malloc.c#L50)

### Поиск и изменение корзин

- **`bin_index(size)`** вычисляет индекс класса, удваивая начальный предел 64 до тех пор, пока он не покроет размер. При достижении последнего класса возвращает его индекс для любого оставшегося размера. [Код](user/malloc.c#L56)
- **`bin_insert(block)`** добавляет блок в голову корзины его текущего размера. Записывает в блок пару ссылок, связывает прежнюю голову с новой и обновляет `bins[index]`. [Код](user/malloc.c#L69)
- **`bin_remove(block)`** исключает блок из корзины. Если у блока есть предшественник, обновляет его ссылку. При удалении головы записывает следующего соседа в `bins`. Если следующий сосед существует, исправляет и его обратную ссылку. [Код](user/malloc.c#L81)
- **`find_block(size)`** начинает с `bin_index(size)` и идёт к более крупным корзинам. Выбирает первый блок, чей полный размер не меньше требуемого, удаляет его из корзины и возвращает вызывающей функции. При исчерпании кандидатов возвращает `0`. [Код](user/malloc.c#L94)

### Изменение списка по адресам

- **`link_block(block)`** связывает блок с уже заданными в `block->prev` и `block->next` соседями. Для отсутствующего соседа обновляет соответствующий конец списка (`heap_first` или `heap_last`). Используется при появлении новой области, разделении и объединении блоков. [Код](user/malloc.c#L110)
- **`adjacent(left, right)`** проверяет физическую смежность диапазонов. Конец левого блока должен совпадать с началом принадлежащей аллокатору области справа, то есть с адресом правого заголовка минус его `padding`. [Код](user/malloc.c#L123)
- **`merge_blocks(left, right)`** объединяет два смежных блока, подготовленных вызывающей функцией. К размеру левого добавляет размер правого и его начальное выравнивание. Правый заголовок становится частью общей полезной области, левый блок получает следующего соседа правого, а `link_block` исправляет обратную ссылку или хвост списка. [Код](user/malloc.c#L130)

### Работа с `sbrk`

- **`grow_heap(size)`** читает текущую границу через `sbrk(0)` и вычисляет число недостающих байтов. Для непосредственно примыкающего свободного хвоста это `size - tail->size`, для нового блока — `size + padding`. Округляет результат вверх до страницы и проверяет, что аргумент помещается в `int`. После успешного `sbrk` либо извлекает прежний хвост из корзины и увеличивает его размер, либо инициализирует новый заголовок и присоединяет его к списку по адресам. Возвращает блок для выделения. При ошибке возвращает `0`, оставляя списки в прежнем состоянии. [Код](user/malloc.c#L138)
- **`trim_heap(block)`** принимает свободный хвост, который ещё предстоит поместить в корзину. Округляет `size + padding` вниз до страницы, проверяет размер сохраняемого остатка и ограничивает величину сдвига наибольшим кратным странице значением, допустимым для `int`. Если конец блока совпадает с `sbrk(0)`, пытается вернуть страницы. Если весь блок возвращён, удаляет его из списка, пользуясь сохранённым указателем на предшественника. При частичном возврате уменьшает размер блока и добавляет его в корзину нового класса. Если граница осталась прежней, вставляет исходный блок в корзину. [Код](user/malloc.c#L171)

### Трассировка и публичный интерфейс

- **`dump_heap(operation, requested, ptr)`** печатает в `stderr` результат одной операции. Показывает её аргументы, фактическую границу сегмента, все заголовки с состоянием `used` или `free`, размеры и адреса блоков в непустых корзинах. В первой строке `ptr` указывает на пользовательскую область, в строках списка выводятся адреса заголовков. Сумма `used` складывается из исходных размеров живых запросов, `reserved` включает заголовки, свободные блоки и байты выравнивания, принадлежащие аллокатору. `free payload` равен сумме размеров свободных блоков за вычетом их заголовков. Процент вычисляется целочисленно. Для пустой кучи выводится `0/0 bytes (0%)`. [Код](user/malloc.c#L200)
- **`malloc_debug(enabled)`** устанавливает флаг трассировки в пользовательском адресном пространстве процесса. Ненулевое значение включает вывод, ноль выключает. Флаг считывается после завершения изменений в `malloc` и `free`. Ошибочный `malloc` и `free(0)` завершаются без снимка, поскольку куча при этих операциях остаётся в том же состоянии. [Код](user/malloc.c#L232)
- **`malloc(nbytes)`** переводит размер в `uint64`, прибавляет заголовок, округляет до 16 байт и применяет нижнюю границу в 48 байт. Получает кандидата через `find_block` или `grow_heap`. Если после выделения остаётся как минимум 48 байт, формирует из них свободный блок, связывает его с соседями и помещает в корзину. Более короткий остаток включается в занятый блок. В заголовке записывает исходный запрос, сбрасывает `available`, при включённой трассировке печатает состояние кучи и возвращает адрес сразу после заголовка. Если кандидат отсутствует, возвращает `0`. [Код](user/malloc.c#L238)
- **`free(ptr)`** сразу завершается для нулевого указателя. Для ненулевого восстанавливает заголовок по адресу пользовательской области, сохраняет исходный размер для трассировки и помечает блок свободным. Проверяет левого, затем правого соседа. Каждый свободный смежный сосед удаляется из своей корзины до изменения размера при слиянии. Полученный блок помещается в корзину либо передаётся в `trim_heap`, если он стал последним в списке. После этого при включённой трассировке выводится итоговое состояние. Указатель должен происходить из успешного `malloc` и освобождаться один раз. [Код](user/malloc.c#L268)

## Функции `user/malloctest.c`

- **`check(ok, message)`** проверяет условие. При нарушении печатает причину в `stderr` и завершает процесс с кодом 1, чтобы тест остановился на первой нарушенной проверке. [Код](user/malloctest.c#L11)
- **`test_list()`** создаёт односвязный список из четырёх узлов со значениями от 0 до 3. Проверяет, что для узлов хватает страницы. Удаляет второй узел и убеждается, что оставшаяся цепочка цела. Новый узел того же размера должен получить прежний адрес. Затем функция проверяет порядок элементов, освобождает все узлы и сравнивает `sbrk(0)` с начальным значением. [Код](user/malloctest.c#L20)
- **`test_coalescing()`** выделяет три соседних блока по 96 байт. После освобождения первых двух запрашивает 192 байта и проверяет, что новый блок начинается по прежнему адресу первого блока, а граница сегмента не сдвинулась. После заполнения объединённого блока проверяет контрольный байт в третьем блоке. В конце функция проверяет возврат страницы. [Код](user/malloctest.c#L58)
- **`test_large()`** удерживает однобайтовый блок и выделяет `2 * PGSIZE + 17` байт. Проверяет рост на целое число страниц, заполняет выделенную область и читает байты в начале, на расстоянии страницы и в конце. Затем освобождает крупный блок и проверяет частичный возврат страниц и сохранность малого блока. После освобождения малого блока граница должна вернуться к исходному адресу. [Код](user/malloctest.c#L81)
- **`test_direct_sbrk()`** создаёт между областями аллокатора однобайтовый промежуток прямым вызовом `sbrk(1)`. Проверяет выравнивание следующего выделения и сохранность контрольного байта при освобождении блоков с обеих сторон промежутка. Удаляет свой байт через `sbrk(-1)`, повторно использует нижнюю страницу и проверяет её возврат. Вызовы на один байт в этом тесте выполняет само приложение. [Код](user/malloctest.c#L107)
- **`main(argc, argv)`** включает трассировку при запуске `malloctest`. Параметр `-q` выключает вывод снимков. После основных тестов проверяет отказ на максимальном запросе типа `uint`, освобождение блока от `malloc(0)` и безопасный вызов `free(0)`. При успехе печатает `malloctest: OK` и завершает процесс с кодом 0. [Код](user/malloctest.c#L131)

## Проверка в QEMU

Проверка выполнена на Fedora 45 с QEMU 11.1.3 и RISC-V GCC 16.2.1. Для сборки и запуска использовались пакеты `qemu-system-riscv-core`, `gcc-riscv64-linux-gnu` и `binutils-riscv64-linux-gnu`.

В корне репозитория запускается `make qemu`. Следующие команды вводятся в оболочке xv6.

```text
malloctest
malloctest -q
usertests -q
usertests mem
```

| Команда | Результат |
| --- | --- |
| `malloctest` | `malloctest: OK`. В выводе присутствовали снимки после выделения и освобождения. |
| `malloctest -q` | `malloctest: OK`. Снимки кучи отключены. |
| `usertests -q` | `ALL TESTS PASSED`. Прошли все 68 быстрых тестов. |
| `usertests mem` | `ALL TESTS PASSED`. Отдельно подтверждено выделение до исчерпания памяти и повторное выделение после освобождения. |

### Фрагмент трассировки после первого выделения узла

```text
heap after malloc (16 bytes, 0x0000000000005020), brk=0x0000000000006000
  0x0000000000005000 used size=48 requested=16
  0x0000000000005030 free size=4048 requested=0
  bin <=4096: 0x0000000000005030
  used=16/4096 bytes (0%), free payload=4016 bytes
```

Первая страница начинается по адресу `0x5000`, пользовательские данные узла — по адресу `0x5020`, на 32 байта дальше. Блок узла занимает 48 байт. Остальные 4048 байт страницы образуют свободный блок, из которого 4016 байт потенциально доступны для пользовательских данных. Доля `16 / 4096` равна примерно 0,39%, поэтому целочисленный вывод показывает `0%`.

В тесте крупного выделения `malloc(8209)` сдвинул границу с `0x6000` на `0x8000`. После `free` крупного блока граница вернулась к `0x6000`, а маленький блок сохранил свой байт. Его освобождение вернуло границу к `0x5000` и дало итоговую строку `used=0/0 bytes (0%), free payload=0 bytes`.
